FAILURE_MODES.TXT 01 / WHY AGENTS SPIRAL [ □ ]
01

THE EPITEMIC CRISIS

Why coding agents keep breaking your code.

§ 1.0

AI coding agents enter every turn with a fresh brain: zero working memory of yesterday's decisions, blind trust in their own plausible output, and a persistent habit of silently guessing when instructions are vague.

The Drama (Failure Mode) What Actually Happens How Totally Shuts It Down
Faking It (No Proof) Agent assumes untested code works because the syntax looks pretty. Receipt Tags: Mandatory [SAW_IT_MYSELF] or [NO_RECEIPTS] tags on every handoff claim (INV-003).
Silent Guessing Agent encounters vague requirements and secretly compiles a wild guess into code. Ask First, Don't Guess: Agent halts during scoping and asks clarifying questions before building (INV-009).
Projecting Assumptions Agent projects standard package managers or framework idioms not present in the files. Drop the Assumptions: Agent audits priors on entry and relies only on verified repository files (INV-010).
Cheesy Workarounds Agent hits unexpected test friction and sneaks around it with a cheesy fallback hack. Huge Red Flag: Friction triggers an immediate stop-and-inquire routine; no silent hack routing (INV-007, INV-009).
Deleting Old Guards Agent deletes an unfamiliar constraint or boundary without knowing what it protected. Why Is This Even Here?: Must trace the originating decision (D-NNN) before altering any guard (INV-004, INV-009).

PROOF_TAGS.TXT 04 / SHOW ME THE RECEIPTS [ □ ]
04

EPISTEMIC TAGGING

Receipt Tags & Negative Proof Grounding.

§ 4.0

Never trust an assertion without a receipt. Totally enforces formal epistemic classification on every claim.

Receipt Tag Plain English Meaning Vedic Equivalent When to Use It
[SAW_IT_MYSELF] Directly run and observed in this session Pratyakṣa When a test command ran cleanly and you saw the terminal output with your own eyes.
[OBVIOUSLY] Logically derived from types, schemas, or proofs Anumāna Static type checks, AST linting, and mathematical invariants that must hold true.
[GOSPEL] Decreed by maintainer contract or specification Śabda Documented requirements, schema contracts, and maintainer specifications.
[VIBE_CHECK] Working hypothesis explaining an anomaly Arthāpatti An unexplained failure or suspected cause awaiting empirical reproduction.
[NO_RECEIPTS] Explicit boundary of non-observation Anupalabdhi Things that have not been run or tested this session. The honest admission of limits.

CHEAT_SHEET.TXT 06 / QUICK REFERENCE [ □ ]
06

QUICK REFERENCE

The Totally Cheat Sheet.

§ 6.0

Copy-paste commands, prompts, and Non-Negotiables for daily agent sessions.

Session Entry Routine

1. Read docs/HANDOFF.md
2. Read docs/INVARIANTS.md
3. Run python3 tools/check_totally.py --template
4. Inspect git status

Session Exit Routine

1. Run offline verification tests
2. Rewrite docs/HANDOFF.md (under 80 lines, with Receipt Tags)
3. Run python3 tools/check_totally.py

AI Coding Assistant Starter Prompt

You are an agent operating under Totally in totally/. Read docs/HANDOFF.md and docs/INVARIANTS.md first. Never guess silently; if anything is ambiguous, ask clarifying questions before editing code. Show me the receipts. Run python3 tools/check_totally.py to verify your work.

The Ten Non-Negotiables

  • INV-001: Zero External Baggage (standard library only)
  • INV-002: One Source of Truth (no duplicate descriptions)
  • INV-003: Show Me the Receipts (mandatory Receipt Tags)
  • INV-004: Two-Way Sync (reciprocal reference checks)
  • INV-005: Keep It Short (80-line Group Chat cap)
  • INV-006: No Em Dashes, Seriously (zero em dashes)
  • INV-007: Catch the Red Flag (negative proof grounding)
  • INV-008: Keep It Tight (under 25 words per rule)
  • INV-009: Ask First, Don't Guess (clarify upfront)
  • INV-010: Drop the Assumptions (no prior projection)

AUTOMATION

The Vibe Linter: Zero-Dependency Guard.

Prose guidelines without code enforcement are just wishes. The Vibe Linter turns the Non-Negotiables into a binary build gate.

Bidirectional Check

Ensures that every Non-Negotiable cited anywhere exists in docs/INVARIANTS.md, and every rule defined there is cited in the living documents.

Receipt Tag Scanner

Scans every capability assertion in docs/HANDOFF.md to guarantee that an explicit Receipt Tag is present.

Em Dash Firewall
