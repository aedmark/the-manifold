GOLDFISH.TXT 01 / THE FAILURE [ □ ]
01

THE FAILURE

Short sessions forget on purpose.

§ 1.0

A fresh context window is a feature. It is also where project memory goes to die. The model is not failing; the handoff between sessions is missing.

01

The constraint that was never written down

Session two adds a second writer because the first one's rule lived in a chat that closed. The code is fine; the reason is gone.

02

The decision that gets re-litigated

Three days later, a new agent proposes the schema you rejected for a reason nobody recorded. The argument starts from zero.

03

The claim that outlives its evidence

The README says the export works. The test was last run before the format changed. Now the docs and the code are both confident, and only one is right.

  1. Session 01

    Feature ships. The chat holds the why.

    CONTEXT / INTACT
  2. Session 04

    A new session misses a constraint. It is rediscovered in review.

    CONTEXT / LEAKING
  3. Session 10

    The docs contradict the code. Nobody knows which one is current.

    CONTEXT / LOST

The problem is not that the model forgets. It is that the repository never told it what to remember.

PROTOCOL.TXT 02 / THE WAGER [ □ ]
02

THE PROTOCOL

The repository becomes the memory.

§ 2.0

The Manifold assigns every kind of truth to one file, then separates the two speeds at which truth changes. Current state is rewritten. History is appended. Plans keep their IDs.

REWRITE THE PRESENT

Current truth

If a statement is no longer true, it does not stay in the file to look true.

  • docs/HANDOFF.md says what works, what is unproven, and what is next.
  • docs/ARCHITECTURE.md describes the system as it exists now.
  • Stale text is deleted, not kept to make the document look thorough.

APPEND THE PAST

Why it happened

A reversal supersedes; it does not erase. The next session can see the road that was already ruled out.

  • docs/DECISIONS.md keeps the choice, the alternatives, and the consequence.
  • ROADMAP.md keeps permanent IDs and what a failed attempt taught you.
  • docs/CHANGELOG.md keeps what a user would notice.
  1. REWRITE

    HANDOFF

    What is true now.

  2. STABLE

    ROADMAP

    What happens next.

  3. APPEND

    DECISIONS

    Why we chose it.

  4. APPEND

    CHANGELOG

    What users noticed.

One fact, one owner. If two documents can disagree, one of them is redundant. Link to the owner instead of copying the fact.

One standard-library Python file. It checks placeholders, IDs, cross-references, links, duplicate sessions, and the size of the handoff. It is the only thing in the template that runs.

SESSION.TXT 04 / THE LOOP [ □ ]
04

THE LOOP

A session has a beginning, a middle, and a handoff.

§ 4.0

The protocol is deliberately boring. That is the point: the next session should not have to guess what the last one did, or why.

  1. 01

    Read

    Open docs/HANDOFF.md, the roadmap item, and the relevant architecture and testing sections. Check git status before touching anything.

    START
  2. 02

    Scope

    State one reviewable change. Protect work you did not create. If the scope is unclear, stop and ask rather than widening it.

    SCOPE
  3. 03

    Build

    Record durable choices as they happen. Add newly discovered work to the roadmap only when it is genuinely out of scope for this change.

    WORK
  4. 04

    Verify

    Run the checks that match the change. Report what passed, what failed, and what was not run. A partial pass is not a full pass.

    PROOF
  5. 05

    Hand off

    Rewrite current state, append the session entry, and run python3 tools/check_docs.py. Leave the next action, not a diary.

    HANDOFF

CHECK_DOCS.PY 05 / THE CHECKER [ □ ]
05

THE CHECKER

A handoff that lies should fail the build.

§ 5.0

tools/check_docs.py is a single standard-library Python file. It does not read your code. It reads the contracts and refuses the mistakes that make a handoff lie.

REFUSES / EXIT 1

Hard errors

  • A {{placeholder}} left in a document.
  • A roadmap ID used twice, filed under the wrong phase, or with an unknown checkbox.
  • A decision used twice, out of order, or superseded by a missing or earlier decision.
  • An open question defined twice.
  • A P-, D-, or Q- reference that resolves to nothing.
  • Two session-log entries with the same number.
  • A relative link, or a path in the AGENTS.md layout table, that points at nothing.

WARNS / EXIT 0

Hygiene

  • The handoff has no Last updated line, or it is older than the newest session entry.
  • The session log has more than ten entries; older ones belong in the archive.
  • Current state has grown past eighty lines.

Warnings do not fail the run. They are the moments to rewrite, archive, or cut.

ACTUAL_OUTPUT.TXTTHIS REPOSITORY / 2026-11-01
$ python3 tools/check_docs.py --template
0 error(s), 0 warning(s) in 13 file(s)

Why --template? This repository is the blank template. Its own documents still contain {{placeholders}}, deliberately. --template tells the checker that the blanks are expected. After you adopt it, drop the flag; every remaining blank becomes an error.

What a clean run proves. That the documents are internally consistent: IDs resolve, links exist, sessions are unique, and the handoff is inside its limits. It does not prove that the prose matches the code. That is what tests, diffs, and the does not prove column are for.

INSTALL.TXT 06 / ADOPT [ □ ]
06

ADOPT

Copy the memory, not the ceremony.

§ 6.0

The Manifold is a directory, not a dependency. Clone it, replace the blanks, delete what does not apply, and make the checker part of the day.

COMMAND.TXTTHREE LINES TO A CLEAN RUN
$ git clone https://github.com/aedmark/the-manifold my-project
$ cd my-project
$ python3 tools/check_docs.py --template

  1. Copy the files. Start from the clone, or drop the contents into an existing repository at the root.
  2. Replace the blanks. Every {{placeholder}} is a decision the template cannot make for you. Run the checker without --template to list them.
  3. Delete what does not apply. Remove optional documents, their links, and their rows in docs/README.md. A small, truthful set beats a complete, abandoned one.
  4. Describe what exists. Record inherited choices as accepted decisions instead of pretending they were made during the migration. Put important gaps in the roadmap.
  5. Seed the next session. Write the current state and the next real action. Run python3 tools/check_docs.py until it is clean.

REQUIREMENTS

  • Python 3 and the standard library. The checker uses re, sys, and pathlib.
  • No packages, no virtual environment, and no network access.
  • Any agent that can read and write files. The protocol is tool-agnostic.
  • Git is useful, but the files are plain Markdown: they work anywhere.

LINEAGE

Two layers of the same idea.

§ 7.0

The Manifold is the agentic extension of The Hypervisor. One shapes the conversation; the other shapes the work between conversations.

THE HYPERVISOR

Gives the model a body.

A framework for Volatile Semantic Leverage: simulated bio-physics, a four-voice Village, sincerity tags, and a lexical firewall. It changes how a model behaves inside a conversation.

  • Semantic bio-physics and a metabolic budget.
  • The Village: Gordon, Mercy, Benedict, Jester.
  • A system prompt you can paste into a cloud model.

THE MANIFOLD

Gives the work a memory.

A repository protocol: Markdown contracts, stable IDs, a recoverable session loop, and a checker. It changes what survives when the conversation closes.

QUESTIONS.TXT 08 / THE SHORT ANSWERS [ □ ]
08

QUESTIONS

The short answers.

§ 8.0
What exactly do I get?

A directory of Markdown contracts, a one-line CLAUDE.md, a roadmap, a handoff format, a documentation map, and tools/check_docs.py. There is no runtime, no package, and no service to sign up for.

Does it work with my agent?

Any agent that can read and write files. AGENTS.md is canonical; CLAUDE.md imports it so Claude Code does not grow a second set of rules. The same files work for Codex, Cursor, Gemini CLI, or a human reading the repository cold.

Do I have to keep all thirteen documents?

No. The template ships a complete set so nothing is missing on day one, but the documentation map is explicit that optional ceremony should be deleted. A small library may need only a README, AGENTS.md, an architecture note, testing guidance, and a concise handoff.

How is this different from a README?

A README explains the project to a newcomer. The Manifold separates current state, history, plans, verification, and security so each can age at its own speed. A single README cannot carry all of them without becoming a diary that contradicts itself.

Is it only for AI projects?

No. It is for any project worked on in short sessions, by people or agents. The examples lean toward software because that is where the handoff problem is easiest to see, but the contracts are plain text and domain-neutral.

What does the checker require?

Python 3 and the standard library. No packages, no network, no build step. It reads the live documents and the archive, and it exits non-zero when a hard error is present.

Can I adopt it in an existing repository?

Yes. Describe the system as it exists, record inherited choices as accepted decisions, and fence off sensitive paths in AGENTS.md. Do not pretend the history was designed; the point is to make the current truth recoverable.

Does it send anything anywhere?

No. The checker reads local files. The template has no runtime, no telemetry, and no external services.

What does a clean run prove?

That the documents agree with each other. It does not prove that they agree with the code, that a decision was wise, or that a test is adequate. The template keeps those limits visible on purpose.

Why “The Manifold”?

The name is borrowed from the Hypervisor's semantic manifold: many local paths, one connected space. The template applies that shape to project memory. Each file is small enough to read in one sitting; together they hold the shape of the work.

What is the licence?

MIT. Use it, fork it, strip it down, or keep only the parts that earn their upkeep.
