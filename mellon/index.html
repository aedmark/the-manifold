SHADOWS.TXT 01 / THE THREE TRAPS [ □ ]
01

THE FAILURE

How short sessions lose the quest.

§ 1.0

A fresh context window keeps an agent fast and sharp. It is also where hard-won project lore vanishes unless the repository enforces strict persistence and pre-build questioning.

01

Guessing in the dark

When requirements admit two valid interpretations, standard agents silently guess one, write 400 lines on the wrong road, and force you to unwind it.

02

Saruman's voice (prior illusions)

Even in a clean window, the model's weights whisper that every project uses the same default frameworks or build steps, blinding it to your actual files.

03

Unverified boasts

A handoff claims a feature works because the code looked plausible. Nobody ran the test suite. The next session builds on a hollow bridge.

The problem is not that the model is a new traveler. It is that nobody left it the Red Book or told it to ask before guessing.

THREE_TIERS.TXT 02 / THREE SPEEDS OF TRUTH [ □ ]
02

THE FOUNDATION

The Elder Runes, The Red Book, and The Watchfire.

§ 2.0

Mellon separates project documentation into three distinct tiers based on how fast truth is allowed to change.

CARVED IN STONE / IMMUTABLE

The Elder Runes

Bedrock laws of the repository (formerly Śruti). Agents may never break, relax, or edit these invariants without explicit maintainer decree.

  • docs/INVARIANTS.md holds INV-001 to INV-010.
  • Every rule is reciprocally linked across the docs.
  • Enforced automatically by check_mellon.py.

APPEND-ONLY / ENDURING LORE

The Red Book of Westmarch

Institutional memory and architecture history (formerly Smṛti). When a decision changes, a new entry supersedes the old so nobody repeats a dead end.

  • docs/DECISIONS.md records why each gate was built.
  • ROADMAP.md tracks quests with permanent IDs.
  • docs/GLOSSARY.md locks down project terms.

REWRITTEN / RIGHT NOW

The Watchfire Log

The Beacon of Minas Tirith (formerly Vartamāna). Overwritten every session and strictly capped at 80 lines so the next traveler sees the truth in one glance.

  • docs/HANDOFF.md holds verified current status.
  • Every claim requires an explicit Proof Badge.
  • Old logs move to docs/archive/.
SIX_CRAFTS.TXT 03 / REPOSITORY ANATOMY [ □ ]
03

REPOSITORY TOPOLOGY

The Six Crafts of the Lore-Masters.

§ 3.0

Where Vedas organizes the repository around the six classical Sanskrit Vedāṅgas, Mellon maps the exact same six structural disciplines into plain English and Middle-earth lore.

01 / THE FELLOWSHIP QUEST LOOP (FORMERLY KALPA)

The 5-Stage Session Ritual

Every session walks the same five steps: Scouting (read & drop priors), Council of Elrond (scope & ask clarifying questions), The Forge (build), Trial at Khazad-dûm (verify), and Watchfire (handoff), with a Turn Back at Caradhras loopback whenever a premise breaks.

02 / THE PALANTÍR LINTER (FORMERLY VYĀKARAṆA)

Bidirectional Seeing-Stone

tools/check_mellon.py validates every cross-reference in milliseconds. It blocks dangling IDs, completed tasks left in Next steps, missing Proof Badges, and broken relative links.

03 / MITHRIL ECONOMY (FORMERLY CHANDAS)

Light as a Feather, Hard as Dragon Scales

Enforces strict token and line bounds (INV-005, INV-008). The Watchfire handoff is capped at 80 lines, and architectural rules are forged in Mithril Prose (under 25 words, zero fluff).

04 / NO BLACK SPEECH (FORMERLY ŚIKṢĀ)

The Lexical Firewall (INV-006)

Bans em dashes, sycophantic chat openers, and robotic filler across all documentation, code comments, and commits. Plain declarative English keeps the signal clean.

05 / THE ELVISH LEXICON (FORMERLY NIRUKTA)

Canonical Glossary

Maintains unambiguous project vocabulary in docs/GLOSSARY.md and AGENTS.md so terms never drift across different models or sessions.

06 / THE SHIRE RECKONING (FORMERLY JYOTIṢA)

Permanent Quest IDs

Tracks work in ROADMAP.md with permanent identifiers (P1-01, P2-03). Quests are never renumbered; dropped quests record why the path was abandoned.

PROOF_AND_GATES.TXT 04 / VERIFICATION & INQUIRY [ □ ]
04

PROOF & HERMENEUTIC SAFEGUARDS

Ranger Proof Badges, Sting's Blue Glow & The Doors of Durin.

§ 4.0

In Mellon, vague claims like "the parser works" are forbidden. Every assertion carries a Proof Badge (INV-003), every bugfix requires Sting's Blue Glow (INV-007), and every ambiguity triggers a clarifying question at the Council of Elrond (INV-009).

The Five Ranger Proof Badges (Plain English)

[OBSERVED] Eyes of the Ranger: Directly verified by running a test or command in this session.
[DEDUCED] Lore-master's Deduction: Invariantly proved from static types, schemas, or axioms.
[CONTRACT] Word of the Council: Formal rule defined in Elder Runes or maintainer policy.
[HYPOTHESIS] Rumor in the Shire: Working theory for an anomaly; requires empirical proof.
[UNTESTED] Uncharted Wilds ("Here Be Dragons"): Explicit boundary of what was not run this session.

The 5-Step Ranger's Trial (With Sting's Blue Glow)

When fixing bugs or adding behavior, agents follow this five-step proof (replacing the Sanskrit Nyāya Pañca-Avayava):

01 The Claim State the required behavior or Elder Rune clearly.
02 Track the Orc Identify the exact root cause or missing check in the existing code.
03 Sting's Blue Glow Write a test for the bug and watch it fail on the old code first (glow blue like Bilbo's blade when Orcs are near, INV-007). A test that passes on broken code is a dull blade.
04 The Forge Apply the minimal, surgical code change required to fix the defect.
05 The Clear Blade Re-run the test suite, observe clean passage, and badge the result with [OBSERVED].

CHEAT_SHEET.TXT 06 / QUICK REFERENCE [ □ ]
06

QUICK REFERENCE

The Fellowship Cheat Sheet.

§ 6.0

Copy-paste prompts, commands, and Elder Runes for daily agent sessions.

The 5-Stage Quest Loop

1. Scouting: Read docs/HANDOFF.md & docs/INVARIANTS.md; drop Saruman's Voice (INV-010)
2. Council of Elrond: Scope 1 change, check Doors of Durin, ask questions (INV-009)
3. The Forge: Build in Mithril Prose; Turn Back at Caradhras if premises break
4. Khazad-dûm: Verify with Sting's Blue Glow (INV-007); honor "You Shall Not Pass!"
5. Watchfire: Update docs/HANDOFF.md (<=80 lines) & run python3 tools/check_mellon.py

Copy-Paste Session Opener for Any AI Agent

Read mellon/AGENTS.md, mellon/docs/INVARIANTS.md, and mellon/docs/HANDOFF.md. State what is proven, what is untested, and the next quest item. Ban Saruman's Voice (do not assume conventions not in the files), ask clarifying questions on any Riddles in the Dark, and propose one small change before writing code.

The Ten Elder Runes (INV-001 to INV-010)

INV-001 (Travelling Light): Zero external dependencies; Python stdlib only.
INV-002 (One Ring Rule): Every project fact has exactly one authoritative home file.
INV-003 (Ranger Marks): Every handoff claim requires an explicit Proof Badge.
INV-004 (Palantír Reciprocity): Bidirectional link and ID integrity across all docs.
INV-005 (80-Line Watchfire): Current state in HANDOFF.md never exceeds 80 lines.
INV-006 (No Black Speech): Zero em dashes or robotic AI filler in prose or comments.
INV-007 (Sting's Blue Glow): A new test must fail on the old bug before trusting the fix.
INV-008 (Mithril Prose): Distill learnings into dense rules under 25 words.
INV-009 (Council of Elrond): Zero silent assumptions; ask clarifying questions before building.
INV-010 (Ban Saruman's Voice): Never project pre-trained defaults onto the repository.
